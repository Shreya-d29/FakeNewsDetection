# TruthLens AI — Fake News Detection Using Deep Learning

TruthLens AI is a deep learning and NLP project that classifies news articles as **REAL or FAKE** using labelled text data. It compares five neural network architectures to evaluate their classification performance.

**Note:** The project requires a dataset and trained model artifacts before predictions and evaluation metrics become available. It is a text classifier, not an independent fact-checking system.

## Features

- News text preprocessing and tokenization.
- Stratified 70/15/15 train, validation, and test split.
- Five model training workflows: Dense, SimpleRNN, LSTM, GRU, and DistilBERT.
- Model comparison using accuracy, precision, recall, F1-score, and confusion matrices.
- Training and validation loss/accuracy visualizations.
- FastAPI backend for inference and evaluation results.
- React + TypeScript frontend with Analyze, Dashboard, Models, Performance, Dataset, and About pages.
- Explicit unavailable states when trained models or results are missing.

## Technology Stack

- **Language:** Python
- **Deep Learning:** TensorFlow/Keras and Hugging Face Transformers, according to the model implementation
- **NLP:** Tokenization, sequence padding, embeddings, transformer tokenization
- **Data Processing:** Pandas, NumPy, scikit-learn
- **Backend:** FastAPI
- **Frontend:** React, TypeScript, Vite

## Dataset and Preprocessing

The project supports the ISOT Fake News Dataset CSV format:

```text
data/raw/Fake.csv
data/raw/True.csv
```

The pipeline combines headlines and article text, removes HTML, replaces URLs with a token, normalizes whitespace, removes empty and duplicate examples, and generates a consistent label mapping.

Data is split into training (70%), validation (15%), and testing (15%). Vocabulary-based tokenizers are fitted only on training data. DistilBERT uses its own pretrained tokenizer.

## Model Comparison

| Model | Purpose | Main limitation |
|---|---|---|
| Dense Neural Network | Baseline text classification | Limited inherent sequence modelling |
| SimpleRNN | Learns sequential patterns | Struggles with long-term dependencies |
| LSTM | Uses gates to retain sequential information | More complex recurrent computation |
| GRU | Gated sequence learning with a simpler structure | Performance depends on the dataset |
| DistilBERT | Pretrained contextual language representations | Higher computational requirements |

All models should be evaluated on the same held-out test split using their appropriate preprocessing. The best model must be selected using actual evaluation results, not assumed in advance.

## Training and Evaluation

The models learn from labelled examples using forward propagation, a classification loss function, backpropagation, and an optimizer such as Adam when configured.

Evaluation includes:

- **Accuracy:** Overall proportion of correct predictions.
- **Precision:** Reliability of predictions for the selected positive class.
- **Recall:** Proportion of positive-labelled examples correctly identified.
- **F1-score:** Harmonic mean of precision and recall.
- **Confusion matrix:** Breakdown of correct and incorrect classifications.

Training histories and evaluation artifacts are saved for visualization and model comparison. Actual scores must be generated by running the training and evaluation pipelines.

## System Workflow

```text
News Dataset → Preprocessing → Data Splitting
             → Model Training → Evaluation
             → Saved Model → FastAPI → React UI
```

The API exposes model availability, predictions, dataset statistics, and evaluation results through the routes implemented in the backend.

## Limitations

- Predictions depend on patterns learned from the training dataset.
- A REAL prediction does not prove that a claim is factually true.
- The system does not browse the web or independently verify sources.
- Model performance may vary on unfamiliar news topics or sources.
- Missing models and metrics are displayed as unavailable rather than fabricated.
